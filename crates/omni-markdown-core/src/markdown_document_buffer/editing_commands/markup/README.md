# Portable Markdown keyboard commands

This module implements the core `InsertNewline` and `DeleteMarkupBackward` plans used by the native editor. It operates on the canonical piece tree and returns the shared editing-command outcome. A declined Backspace leaves grapheme deletion to the native text view. Enter invokes the ordinary newline/indent fallback when Markdown continuation declines. The caller validates the primary UTF-16 selection and commits active IME input before calling the core command.

## Responsibilities and ownership

| Module | Responsibility |
| --- | --- |
| `markup.rs` | Select active command context, continue or exit markup, and plan default Enter. |
| `source.rs` | Borrowless scalar and physical-line cursors over immutable canonical piece descriptors. |
| `context.rs` | Own the transient active container path, paragraph laziness and opaque-block lifetime. |
| `markers.rs` | Recognize exact markers, structural indentation, interruption, thematic breaks and complete fence runs. |
| `foreign_blocks.rs` | Track finite HTML block identities and dispatch applicable default indentation. |
| `html_indentation.rs` | Resolve covered tag/body indentation from source-name ranges and finite lexical state. |
| `transaction.rs` | Generate finite primary edits, stream consecutive sibling renumbering and publish atomically. |
| `markup_tests.rs` | Execute frozen upstream differential cases, failure injection and resource regressions. |

Structural parser coordinates and command marker coordinates are deliberately distinct. For example, a tab-only bullet parent owns its nested list's indentation even though the preserved command regex omits that parent from the continuation prefix. An ordered parent may preserve zero literal spaces in its command marker while consuming a tab structurally. Logical visual columns, physical scalar offsets and native UTF-16 units are therefore separate metadata.

All parser state belongs to one explicit command. There is no idle parser, document-sized String, paragraph mirror, retained complete syntax tree or per-sibling edit list. Active container/HTML-element metadata is **O(active nesting depth)**, not a constant-size claim. Source-piece cursors retain an AVL-height stack. Whitespace trimming walks backward through 4 KiB windows; a partial initial UTF-8 scalar is revisited in the preceding window. Thematic rejection retains three finite suffix boundaries so repeated same-bullet nesting does not rescan an identical failed suffix quadratically.

## Canonical edits, history and limits

A command owns at most two primary source edits and two ordered-list selectors. Renumbering stops at the first original nonconsecutive sibling number. Further sibling edits are regenerated by sequential source passes. Commands may need linear prefix/suffix work to establish container ownership, list looseness, opaque context or renumbering; they are not viewport-only operations.

Fewer than 4,096 edits use sparse structural replacements and share unchanged body pieces. At 4,096 or more edits, a fixed 4 KiB scratch builder streams one new canonical replacement envelope. Dense output and its structural undo root are normal canonical storage. Both paths preflight the complete append budget before output, then use `command_transaction::commit_command` for a single unpublished candidate root, future selection validation and one history publication. Failed preparation restores appended segments, tail length and used-byte counters; text, generation, selection, undo and redo remain unchanged. The session's 32 MiB lifetime append budget still applies, including after save and undo.

The UTF-16 receipt covers the complete original source envelope, its net unit delta and the final primary selection. Existing CRLF/CR/LF source bytes stay unchanged; newly generated breaks use the preserved editor's configured physical separator choice. Supplementary scalar boundaries remain valid through undo/redo.

## Frozen compatibility evidence

`reference.json` contains **4,328 actual CodeMirror command queries over 117 synthetic source inputs**. The generator executes `insertNewlineContinueMarkup` and `deleteMarkupBackward` from `@codemirror/lang-markdown` 6.5.2. When the Markdown Enter export declines, it executes `insertNewlineAndIndent` from `@codemirror/commands` 6.11.0. It checks every scalar-aligned caret plus nonempty/reversed selections and serializes results back to physical native UTF-16 coordinates.

Covered cases include list/quote continuation and exit, checkbox reset, loose lists, nested and lazy containers, sequential/nonconsecutive ordered numbering, tab-padded parents and children, marker-boundary affinity, Unicode and physical separators, thematic breaks, fences, foreign HTML blocks and the declared default indentation cases. The fixture records versions and SHA-256 hashes for 11 participating executable entry files. Normal Rust tests consume the frozen fixture and need neither Node nor an installed CodeMirror dependency.

This evidence establishes the declared frozen contexts. The streaming scanner is not a complete replacement for CodeMirror/Lezer's extensible Markdown, HTML, JavaScript or CSS parsers. Embedded indentation implements the covered lexical rules, including simple unary script continuation; it does not claim arbitrary embedded-language grammar equivalence. New supported contexts require an upstream counterexample and regression evidence rather than an unverified blanket parity claim.

To verify or deliberately regenerate with a preserved editor checkout whose own dependency graph is already installed, run from this repository root:

```sh
node scripts/generate-markup-reference.mjs /path/to/preserved-editor --check
node scripts/generate-markup-reference.mjs /path/to/preserved-editor
```

The baseline directory is explicit. The script installs no packages, rejects version/entry-hash drift, and `--check` never writes the fixture. Regeneration replaces only the synthetic JSON fixture; review that diff and rerun the Rust differential test before accepting it.

## Resource verification

Pure tests cover a giant shared list body, 12,000 ordered items using the dense path, 8,192 nested quote and bullet containers, Unicode trailing whitespace crossing scratch/piece boundaries, append-budget rejection, and failure after actual append while a redo branch exists. These tests assert canonical storage and exact text/history/selection rather than mirroring the planner's internal branch structure.

Run the opt-in 32-sample release profile explicitly:

```sh
cargo +1.99.0 test -p omni-markdown-core --release --features native-markdown-candidate profile_markup_command_resources --locked -- --ignored --nocapture
```

Opening each immutable source snapshot happens outside the timed interval. Samples include the complete pure command and record nearest-rank p50/p95/p99 plus resulting canonical storage counters. This is algorithm/storage evidence, not AppKit input-to-frame latency, peak process RSS or a macOS 14 runtime claim. Native dispatch, IME and resource-release acceptance remain separate plugin gates.

The final local Rust 1.99.0 release run recorded these 32-sample pure-command observations. Inputs are synthetic, snapshots open before timing, and native frame delivery is excluded:

| 4 MiB ordinary line | 0.422 ms | 0.593 ms | 0.729 ms | 1 | 1,025 |

These counters exclude temporary active-path metadata and immutable mapped pages, so they are not a peak-memory measurement. Reproducing the command above is the authority for later machines or source revisions; observed durations are not timing assertions in the normal test suite.
